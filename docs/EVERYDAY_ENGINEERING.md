# Everyday engineering beside NASA Managed

Engineering defaults to **Everyday work** for a new workspace: intent, a short
pathway, manageable cycles, promises, uncertainty, observations and decisions.
Existing NASA workspaces retain **NASA Managed**, including phase/artifact gates,
reviewed baselines, tailoring and evidence history. An owner can change mode with
reason, remaining exposure and a revisit trigger; no phase or old record is reset.

The primary rhythm is: review intent → request a proposed pathway/cycle → inspect
and edit the change set → adopt planning → explicitly start → record observations
and evidence → review/replan/close. Adopting planning does not start work, verify
a promise, accept risk or record an owner-decided trade-off.

Five views keep the result understandable: Pathway, Current cycle, Results,
Why this?, History. The “Why” view retains exact project references, a concise
rationale, known handbook principle and practical control. Results distinguish
reported work, evidence scope/configuration, review and effective owner verification.
Unknown exposure stays unknown; document completion is not product confidence.

## Authority, records and context

Private additive engineering_* version tables hold profiles, intent/agreement,
pathway/cycle/commitment objects, links, pending proposals, cycle configurations
and owner-reported observations. Persistent requirements/risks/decisions reuse
nasa_items; commitments reference exact versions rather than copying promises.

All Everyday AI operations—pathway, cycle, posture, drift, formality—are tool-free
pending proposals with strict schemas, declared local IDs, exact known references
and supplied handbook IDs. No formal document selection is required. They share
NASA's existing eight workspace calls/hour, $1/source-project rolling-day budget,
120,000 input-byte and 6,000 output-token caps, ProviderGate and no automatic retry.
Responses/edits are capped at 10,000 UTF-8 JSON bytes so the complete proposal can
be inspected and edited through the normal bounded owner POST form.

The authoritative context includes current adopted intent/commitments/decisions,
selected task/research/evidence scope, result/configuration references and a
coverage manifest. Legacy ai_draft material is quarantined and read-only.
Full-scope hashes protect beyond bounded summaries. Input plus manifest plus
hash compile under the protected panel/research transaction. Staging and owner
adoption recheck revisions/full digest; a changed context supersedes advice.

Owner adoption validates every member/reference/dependency and appends one atomic
change set. Promises remain unverified, cycles planned and risks unaccepted.
Existing obligations must be structurally carried or explicitly disposed of;
mentioning a commitment in explanatory prose is insufficient. Dependencies must
be closed before a dependent cycle starts. Only the owner starts/reviews/pauses/
replans/closes; no next cycle starts automatically. Scope removal needs an explicit
owner decision, and incomplete closure retains unresolved promises and risks.

Starting/replanning captures exact intent/pathway/item/agreement versions and
available project configuration. The managed project's code reference is separate
from AIcontrol’s own installed SHA; unknown configuration is never invented.
Formal baselines additionally retain the engineering context for comparison;
restoring formal items does not silently restart or roll back cycles/mode.

## Evidence and unknowns

New Everyday promises retain required_scope and configuration_required. Suitable
captured evidence, a separate owner review and explicit owner confirmation are
required for effective verification. Manual captures record scope, configuration
actually tested and limitations with owner-reported provenance. Owner selection of a known required scope and exact expected project
configuration is required before verification; the reviewed tested configuration
must match that expected reference. Fixture/local/live-provider/hosted scopes
cannot silently substitute for one another; captured web text is not an executed
runtime test. Relevant constraint/source changes invalidate effective support.

These new constraints persist across edits/mode changes. Old records and reviewed
snapshots keep their original meaning and hashes; their missing new metadata is
labelled unknown, never upgraded. Every result records its source/scope/limits;
a report of completed work cannot verify a promise by itself.

Unassessed risk stores null ratings with rating_status=not_assessed, rather than a
fabricated 1–5 score or zero/green exposure. Formal readiness and context packs
show that uncertainty. Existing scored risks retain their recorded assessments.

## Human controls and handover

The owner can correct intent/agreement in ordinary forms, edit/adopt/reject a
proposal, choose a cycle, record observations and review evidence without JS.
Advanced JSON remains available for a whole structured proposal. Mode and cycle
history, earlier proposal versions, failed/stale advice and work reports remain
traceable. No credential, private model reasoning or secret-bearing DOM dump is
part of this explanation.

SE Context Pack includes the operating model, current results, evidence metadata,
handbook applications and explicit coverage. Everyday next moves follow current
intent/cycle/evidence rather than the first missing formal document. Formal checks
remain separately labelled. Older baseline/pack omissions mean “not captured.”

Public generation of formal document bundles now stages collaborator proposals
before adoption too. Legacy provider compatibility remains internal; formal AI
reviews remain explicitly advisory, never owner approval or operative authority.
Existing owner, PIN, CSRF, Stop, signing, SSH, budget and update controls remain.

## Validation

`everyday_engineering.php`, `everyday_provider.php`, `everyday_evidence.php`,
`everyday_context_pack.php`, `everyday_http.py` and `everyday_ui.cjs` cover authority,
legacy quarantine, complete-context freshness, references/dependencies, obligation
retention, atomic rollback, unknown risk, scoped proof, cycle ownership, readable
handbook/result traces, mobile/keyboard/no-JS and exports. The four discovered
legacy-dedup/path-retention/dependency/current-cycle bugs have explicit regressions.
Provider/browser fixtures are synthetic. Do not describe them as live model or
hosted website validation.
