# Workspace UI

The redesigned interface uses locally bundled MIT-licensed Tabler 1.7.4 with
AIcontrol's own layout, styles and server-rendered views. It covers PIN setup,
login/lock, release check/review/install and the authenticated workspace.

Workspace views: Overview; Projects & tasks with search and proposal forms;
Agent runs with outputs/usage/evidence; Systems with honest configuration states;
Activity with readable event labels/search. Updates and PIN lock are real links.
Empty, error, disabled-action and review states do not invent agents or progress.
Displayed times use Australia/Perth (AWST); stored event timestamps remain UTC.

## Sources and generated output

- `assets/vendor/tabler-1.7.4.min.css`: pinned upstream CSS, only sourcemap comment removed.
- `assets/vendor/TABLER-LICENSE.txt`, `tabler-package.json`: license and provenance/checksums.
- `assets/app.css`: editable application styles and responsive/contrast rules.
- `ui/Ui.php.tpl`: editable shared helper/icons/standalone shell.
- `src/PanelView.php`: workspace views and forms.
- `assets/panel.css`, `src/Ui.php`: generated by the UI builder.
- The marked generated theme section inside `loader.php` is also built from
  these sources, keeping first-upload PIN/setup styled without extra files.

The standalone `AIcontrolUi` and released `AIcontrolWorkspaceUi` are independent
classes. A future workspace release can update its helper without depending on
which bootstrap theme version is already uploaded.

```sh
php bin/build-ui.php
php bin/build-manifest.php
php bin/build-ui.php --check
php bin/build-manifest.php --check
```

Run UI build before the manifest whenever UI sources change. Do not edit its
generated theme block manually. Both checks run in GitHub Actions. npm package
SHA-512 and registry ECDSA signature were verified on retrieval; the builder
checks the recorded vendored-file hashes. No npm/build tooling is needed on cPanel.

## Browser behavior

No JavaScript is required for navigation, search, forms, disclosure controls or
installation. Native HTML forms preserve CSRF and server validation. PIN and
installer CSS is embedded with a fresh CSP nonce. Workspace CSS is served from
the installed private release through the authenticated loader. SVG/data assets
are local; there are no font/CDN calls. Keyboard focus, skip links, associated
labels, semantic landmarks and current-page navigation are included.

Test responsive layouts, keyboard use, empty and populated workspaces, error
messages and a real GitHub install/update before declaring a UI release ready.
Synthetic run data used for visual testing is not proof of live provider access.

```sh
npm ci --ignore-scripts
PHP_BINARY=php npm run test:ui
```

Node/Playwright/axe are development-only dependencies, not cPanel requirements.
The browser test uses installed Chrome/Chromium when available; otherwise run
`npx playwright install chromium` first. `CHROMIUM_PATH` can select a test browser.
It creates synthetic data in disposable private storage, tests navigation/forms/
search and mobile overflow, and runs axe WCAG A/AA checks. Screenshots and a
sanitized accessibility report go into ignored `test-artifacts/` (override with
`UI_ARTIFACT_DIR`). It makes no provider or GitHub requests. The full real GitHub
installer remains a separate end-to-end release check.

## Applying an update

Upload the new standalone `loader.php` to update the first-load/login/installer
theme. Existing generated PIN/location markers and private state are retained.
Then use Check GitHub → review → Install this checked commit to activate the new
workspace views/assets from the exact tested release. Replacing the bootstrap
alone does not silently replace an existing application release.
